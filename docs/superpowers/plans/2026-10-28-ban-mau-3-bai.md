## Hợp đồng dữ liệu (công cụ Python ghi, Unity đọc)

Mọi task đều dùng chung hợp đồng này. Tên trường viết kiểu `snake_case`. Lớp DTO bên C# dùng **đúng tên trường** này để `JsonUtility` đọc được.

**`lessons/index.json`** có dạng `{"lessons": [{"lesson_id", "lesson_no", "title", "type"}]}`, xếp theo `lesson_no`.

**`lessons/<lesson_id>.json`:**

| Trường | Kiểu / giá trị |
|---|---|
| `schema` | `1` |
| `lesson_id` | ví dụ `"tv1_t1_b13"` (số bài 2 chữ số) |
| `book`, `lesson_no`, `type`, `title` | lấy từ nguồn |
| `new_units` | ví dụ `["u","ư"]`, `["an"]`, `["huyen","sac"]` |
| `source` | `{"pages":[18],"scan_file":"010","verification":"page_verified"}` |
| `review` | `{"status":"chua_duyet","can_duyet":[{"where":"part1[7]","note":"..."}]}` |
| `part1` | danh sách **Step** |
| `part2` | danh sách **Round**, đã dàn phẳng |

**Step:** luôn có `type`. Các trường khác tùy loại; trường không dùng thì bỏ hẳn.

| `type` | Trường |
|---|---|
| `unit` | `text`, `audio`, `hl` |
| `keyword` | `text`, `audio`, `image`, `hl` |
| `analyze` | `rows`: danh sách Item (`text`, `audio`, `hl`) |
| `spell` | `spell`: Spell; `then_text`, `then_audio` (có thể không có) |
| `tone_intro` | `tone`, `text` (tên dấu), `glyph`, `audio` |
| `tone_attach` | `spell`: Spell, `drag_tone` = `true`; `image` |
| `picture` | `image`, `audio` (lời dẫn). Dùng cho tranh trên trang sách không có chữ |
| `words` | `marker`; `items`: Item (`text`, `audio`, `image`?, `note`?, `hl`, `spells`) |
| `reading` | `marker`; `items`: Item (`text`, `audio`, `row`, `spells`) |
| `sentence` | `marker`, `text`, `audio`; `items`: Item cho từng tiếng (`text`, `audio`, `spells`) |

Các kiểu con:
- **Spell:** `{"target","drag_tone","parts":[Part]}`.
- **Part:** `{"kind":"unit"|"join"|"tone","text","audio"}`. Part loại `tone` có thêm `"tone"` với giá trị `huyen`/`sac`/`hoi`/`nga`/`nang`, và `text` là ký hiệu dấu.
- **Span:** `{"s": vị trí bắt đầu, "n": độ dài}`, tính theo ký tự của chuỗi NFC.

**Round:**

| Trường | Ý nghĩa |
|---|---|
| `kind` | `listen_choose`, `look_tone`, `compose` hoặc `listen_picture` |
| `tag` | ví dụ `"look_alike"`; để `""` nếu không có |
| `instruction_audio` | lời hướng dẫn |
| `prompt_audio` | lời đề; có thể là `""` |
| `prompt_text` | chữ mẫu, hoặc khuôn có chỗ trống `_` |
| `base_text` | tiếng gốc (riêng `look_tone`) |
| `image` | tranh đi kèm (riêng `compose`) |
| `options` | danh sách `{"text","audio","image","tone"}` |
| `answer` | vị trí đáp án trong `options` |

**Ký hiệu dấu:** huyền `ˋ` (U+02CB), sắc `ˊ` (U+02CA), hỏi `ˀ` (U+02C0), ngã `˜` (U+02DC), nặng `.` (U+002E). Nếu font thiếu ký hiệu nào thì đổi sang ký tự khác có trong font, và sửa cả `TONE_INFO` lẫn test.

**Mã âm thanh (Telex ASCII):**

| Loại | Cách đặt mã | Ví dụ |
|---|---|---|
| Phụ âm | `am_<telex>` | `am_dd` = "đờ", `am_k` = "ca" |
| Âm cuối `ng` | `am_ng_cuoi` | = "ngờ" |
| Nguyên âm, vần | `van_<telex>` | |
| Dấu | `dau_<tone>` | |
| Một âm tiết | `tieng_<telex>` | |
| Âm tiết không có âm đầu, không dấu, đọc đúng như chữ viết | `van_` | `"u"` → `van_u`, `"an"` → `van_an` |
| Từ hai âm tiết trở lên | `tu_<telex nối _>` | |
| Câu | `cau_b<NN>_<kk>` | |
| Lời dẫn tranh không chữ | `hd_b<NN>_tranh_<kk>` | |
| Hướng dẫn, khen | `hd_*`, `khen_*` | |

**Mã tranh:** `img_b<NN>_<telex>`; tranh dùng chung đặt mã `img_chung_*`. Kí hiệu ● và ⌂ hiện bằng hình `img_chung_em_doc` và `img_chung_luyen_tap`, đặt trước mục tương ứng, giống trong sách.

- Consumes: mọi thứ ở trên.
- Produces: bản mẫu đạt mục 13 của bản thiết kế.

- [ ] **Step 1: Kiểm tra dữ liệu.** `python -m tapdoc validate` phải in `OK`. Lệnh này chạy không kèm `--allow-missing`.
- [ ] **Step 2: Chủ dự án duyệt âm thanh và tranh.** Chạy `python -m tapdoc review` và gửi link `http://127.0.0.1:8765/`. Chủ dự án đánh dấu đạt / không đạt.
  - Tranh không đạt thì tạo lại theo Task 12.
  - Âm thanh không đạt vẫn dùng tạm, đúng theo bản thiết kế.
- [ ] **Step 3: Chủ dự án duyệt các mục `can_duyet`.** In các mục này bằng `python -m tapdoc build`, gồm:
  - tên đọc riêng của "ngan";
  - lời dẫn tranh 5 bạn múa ở bài 4;
  - các tranh vẽ thêm ở bài 42.

  Mục nào chủ dự án yêu cầu sửa thì sửa trong `content/src`, chạy lại `python -m tapdoc build`, rồi chạy lại các test.
- [ ] **Step 4: Build và mở cho chủ dự án thử trọn bài.**
  - Chạy `python run_unity_build.py`, rồi `python run_unity_build.py --launch 1600x720`.
  - Chủ dự án đi hết bài 4, 13, 42, cả Phần 1 lẫn Phần 2.
  - Sau đó mở `--launch 1440x1080` để xem khung cỡ máy tính bảng.
  - Lỗi chủ dự án báo được sửa ngay. Sửa xong thì chạy lại toàn bộ test, build lại, và mở lại cho chủ dự án.
- [ ] **Step 5: Đối chiếu tiêu chí bản mẫu ở mục 13:**

| Tiêu chí | Bằng chứng |
|---|---|
| Đi hết 3 bài chỉ bằng chạm và kéo thả, không cần mạng | `AllLessons_EndToEnd`, cộng với lượt chủ dự án tự thử trên bản build Windows |
| Đánh vần đúng quy tắc 5.1 | `test_spelling`, `test_prototype_content` |
| Phần 1 khớp trang sách, đúng thứ tự | `test_prototype_content`, cộng với chủ dự án duyệt |
| Chữ tiếng Việt hiển thị đúng | `FontCoversAllDisplayText`, `Layout_AllSteps_FitAndNoOverflow`, ảnh chụp màn hình |
| Thay file cùng `id` thì app dùng bản mới | `SwapImageAndAudio_SameId_UsesNewFile` |

- [ ] **Step 6: Ghi quyết định sau khi thử.** Ghi ý kiến của chủ dự án về nhân vật dẫn dắt và phần thưởng vào mục 15 của bản thiết kế. Đây là đầu vào cho kế hoạch bản đầu tiên (bài 1–17).
